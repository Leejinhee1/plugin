# 테스트 시나리오 자동 생성 스킬

대상 설계서: **$ARGUMENTS**

아래 단계를 순서대로 수행하여 테스트 시나리오를 생성하세요.

---

## 1단계: 설계서 분석

`$ARGUMENTS`는 **Figma URL / PDF / 단일 이미지 / 이미지가 든 폴더** 중 무엇이든 될 수 있습니다. 입력 형태를 먼저 판별하세요:

- **Figma URL**(`figma.com/design/...`): 아래 "Figma 설계서 읽기" 절차를 따릅니다. 기획서가 Figma에 사는 경우가 가장 흔합니다.
- **PDF**: Read 도구로 **전체 페이지** 읽습니다 (한 번에 최대 20페이지, 필요 시 분할).
- **이미지 폴더**: 폴더 안의 이미지 파일(`.png`, `.jpg` 등)을 **파일명 순으로 정렬**한 뒤 순서대로 모두 Read 합니다 (여러 장은 한 번의 호출에 병렬로 Read).
- **단일 이미지**: 해당 파일을 Read 합니다.

> **스킵 규칙**: 표지·간지·여백 등 **화면ID(예: HAN_634)도 Description도 없는 페이지**는 분석 대상에서 제외합니다.

### Figma 설계서 읽기

기획서용 Figma 파일은 보통 **캔버스(페이지) 1개에 스펙 페이지 프레임 수십 개**가 깔려 있고, Description 텍스트가 프레임 안에 텍스트 레이어로 들어 있습니다. 스크린샷을 수십 장 읽는 것보다 **메타데이터에서 텍스트를 통째로 뽑는 편이 정확하고 훨씬 쌉니다.**

1. URL에서 `fileKey`(`/design/<fileKey>/...`)와 `nodeId`(`?node-id=418-44944` → `418:44944`)를 추출합니다.
2. `mcp__claude_ai_Figma__get_metadata` 를 `fileKey` + `nodeId` 로 호출합니다.
   - 스펙 덱 전체를 가리키는 노드면 응답이 토큰 한도를 넘어 **파일로 저장**됩니다. 그 경로를 그대로 다음 단계에 넘기면 됩니다.
3. 동봉 스크립트로 페이지별 텍스트를 추출합니다 — **텍스트 레이어의 실제 문구는 `<text>` 노드의 `name` 속성에 들어 있습니다.**
   ```bash
   python3 ${CLAUDE_PLUGIN_ROOT}/skills/planning/test-script/scripts/figma_spec_text.py \
     <get_metadata 결과 파일 또는 저장한 XML> <출력.md>
   ```
   최상위 프레임 = 스펙 페이지 1장으로 묶고, 좌표(y→x) 기준으로 읽기 순서를 복원해 출력합니다.
4. 출력된 텍스트를 Read 해서 2단계로 넘어갑니다. **레이아웃·분기 화살표를 눈으로 봐야 하는 페이지**(프로세스 플로우, 케이스 비교 등)만 `mcp__claude_ai_Figma__get_screenshot` 으로 보완하세요 — 전 페이지를 스크린샷 뜨지 마세요.

> Figma MCP 가 연결돼 있지 않으면 `/hes:mcp-connectors` 로 연결 상태를 먼저 확인하고, 연결이 어려우면 사용자에게 **PDF 내보내기**를 요청해 PDF 경로로 진행합니다.

각 페이지에서 다음을 구조화하여 추출합니다:

### 추출 항목
- **화면명 + 화면ID**: 예) `해외여행모드[MAI_101_1]`, `퀵메뉴 전체보기[MAI_102]`
- **영역명**: 예) ON1.여행지정보, ON2.보유통화영역, 퀵메뉴 영역, 내설정현황
- **CASE 분기 조건**: 예) CASE1. 타임존=해외, CASE2. 타임존=국내
- **Description 텍스트**: 각 영역의 상세 동작 설명
- **터치/액션 동작**: "터치 시 > [이동 대상]" 패턴
- **엣지 케이스**: 외국인, 미로그인, 잔액없음, 데이터 조회중, 보유카드 없음 등
- **회원 분류별 동작**: 미로그인/로그인/외국인/트래블로그 비회원 등

추출 결과를 아래 형식으로 내부 정리합니다:
```
[화면명] > [영역명]
  - 조건: [CASE 조건]
  - 동작: [터치/액션 설명]
  - 이동: [이동 대상 화면ID]
  - 엣지: [특수 조건]
```

## 2단계: 테스트 시나리오 생성

1단계에서 추출한 구조를 기반으로 테스트 시나리오를 생성합니다.

### 시나리오 컬럼 구조
| 컬럼 | 설명 |
|------|------|
| Test ID | `{PREFIX}_{NNN}` (예: TLM_001) |
| 테스트 담당자 | (사용자에게 확인) |
| 로그인 상태 | 공통 / 로그인 / 미로그인 |
| 화면명 | 화면명[화면ID] |
| 영역 | 영역명 (네이티브/웹 구분 포함) |
| 사전조건 | 상태/조건 조합 |
| 시험내용 | 테스트 유형 |
| 테스트 수행 | 구체적 수행 방법 |
| 점검사항/예상결과 | 기대 동작 |

### 시나리오 생성 패턴 (영역당 적용)

**기본 패턴** — 모든 영역에 공통 적용:
1. **페이지 출력**: 해당 영역이 정상 렌더링되는지
2. **데이터 표시**: CASE별 데이터가 올바르게 노출되는지
3. **로딩 상태**: 데이터 조회 중 로딩 UI가 정상인지

**터치 액션 패턴** — "터치 시 >" 가 있는 모든 항목:
4. **이동링크**: 터치 시 정확한 화면으로 이동하는지
5. **팝업 출력**: 터치 시 올바른 팝업이 출력되는지

**CASE 분기 패턴** — CASE 조건이 있는 모든 항목:
6. **조건별 분기**: 각 CASE 조건에서 올바른 동작이 수행되는지

**엣지 케이스 패턴** — 특수 조건:
7. **미로그인**: 미로그인 시 로그인 유도 동작
8. **외국인**: 외국인 전용 동작 (사용 불가, 별도 문구 등)
9. **빈 데이터**: 잔액 없음, 카드 없음, 내역 없음 등
10. **최대값/최소값**: 금액 최대 표기, 텍스트 말줄임 등

### 로그인 상태 분류 기준
- **공통**: 로그인 여부와 무관한 테스트 (네이티브 렌더링, 공통 UI 등)
- **로그인**: 로그인된 상태에서만 확인 가능한 테스트 (잔액 조회, 설정 등)
- **미로그인**: 미로그인 상태의 별도 동작 확인 (로그인 버튼, 접근 제한 등)

### Test ID 채번 규칙
- prefix는 화면명에서 자동 추출 (예: 트래블로그 메인 → TLM)
- 001부터 순차 채번
- 영역 순서: 설계서 페이지 순서 기준

## 3단계: 사용자 확인

생성된 시나리오를 **테이블 형태**로 사용자에게 표시합니다.

표시 형식:
```
### [화면명] > [영역명] ({N}건)
| ID | 로그인 | 영역 | 사전조건 | 시험내용 | 테스트 수행 | 예상결과 |
|----|--------|------|----------|----------|-------------|----------|
| ... | ... | ... | ... | ... | ... | ... |
```

사용자에게 확인:
1. 시나리오 수정/추가/삭제 요청
2. 테스트 담당자 이름 (비워도 됨)
3. Test ID prefix 확인
4. **출력 방식** — 아래 중 선택받습니다:
   - **클립보드 복사** (권장·기본): 권한 불필요, 시트에 바로 붙여넣기
   - **CSV 파일**: `~/Downloads/`에 저장
   - **Google Sheets 자동 작성**: 서비스 계정 권한 필요 (시트 URL도 함께 확인)

> **회사 계정 환경 기본값**: 회사 보안 정책상 서비스 계정 키 발급·공유가 막힌 경우가 많습니다. 출력 방식을 못 정했거나 회사 계정이면 **클립보드 + CSV**를 기본으로 진행하고, Google Sheets는 권한이 확보된 경우에만 권합니다.

---

## 4단계: 시나리오 출력

3단계에서 선택한 방식으로 출력합니다. **클립보드·CSV는 항상 함께 만들어 두는 것을 기본**으로 하세요 (CSV는 백업 겸 재수정 원본).

### 공통 컬럼 순서
`Test ID / 테스트 담당자 / 로그인 상태 / 화면명 / 영역 / 사전조건 / 시험내용 / 테스트 수행 / 점검사항·예상결과`

### (A) CSV 파일 — 기본 산출물
- 파일명: `테스트시나리오_{시트이름}_{날짜:YYYYMMDD}.csv`
- 저장 경로: `~/Downloads/` (사용자가 다른 경로를 지정하면 그쪽)
- 인코딩: **UTF-8 BOM** (엑셀·구글시트 호환), 셀 내 줄바꿈은 공백 치환
- 파이썬 `csv` 모듈로 작성

### (B) 클립보드 복사 — 권한 없이 시트에 붙여넣기 (권장)
CSV를 **탭 구분(TSV)** 으로 변환해 `pbcopy`로 클립보드에 넣습니다. 사용자는 시트 A1에서 `Cmd+V` 한 번으로 붙여넣습니다 (탭 → 9개 컬럼 자동 분리).

```bash
cd ~/Downloads && python3 -c "
import csv
with open('<CSV 파일명>', encoding='utf-8-sig') as f:
    rows = list(csv.reader(f))
print('\n'.join('\t'.join(c.replace(chr(10),' ').strip() for c in r) for r in rows))
" | pbcopy && echo "클립보드 복사 완료 (헤더 포함 N줄, 탭 구분)"
```

안내 문구: "시트 A1 셀 클릭 → `Cmd+V` 붙여넣기 → 9개 컬럼 자동 분리".

### (C) Google Sheets 자동 작성 — 권한 확보 시에만
> **전제**: 이 경로는 사용자가 자신의 머신에 준비해 둔 `sheets_writer.py`(Google 서비스 계정 인증)를 필요로 합니다. 플러그인에 동봉되어 있지 않으므로, 스크립트 경로를 모르면 **사용자에게 물어보고** 없으면 (B) 클립보드로 진행하세요.

시나리오 데이터를 JSON으로 구성하여 sheets_writer.py를 실행합니다:

```bash
echo '<JSON 데이터>' | <사용자의 python> <사용자의 sheets_writer.py 경로>
```

JSON 구조:
```json
{
  "spreadsheet_url": "<사용자가 제공한 Google Sheets URL>",
  "sheet_name": "<시트 이름>",
  "prefix": "<Test ID prefix>",
  "tester": "<테스트 담당자>",
  "scenarios": [
    {
      "login_state": "공통",
      "screen_name": "화면명[ID]",
      "area": "영역명",
      "precondition": "사전조건",
      "test_type": "시험내용",
      "test_action": "테스트 수행",
      "expected_result": "점검사항/예상결과"
    }
  ]
}
```

### 에러 처리 (Google Sheets 경로)
- **credentials_not_found**: 스크립트가 반환하는 설정 가이드를 사용자에게 안내. 단, **회사 계정이라 권한 발급이 어렵다면 (B) 클립보드 복사로 즉시 전환**하라고 먼저 제안합니다.
- **권한 오류**: 서비스 계정 이메일을 시트에 편집자로 공유하도록 안내. 역시 어려우면 클립보드 경로로 전환.
- **기타 실패**: 이미 만들어 둔 CSV로 폴백하고, 클립보드 복사를 안내.

## 4-1단계: 사용자 직접 수정 후 재반영 (선택)

사용자가 출력된 **CSV를 직접 열어 수정**(행 삭제·문구 변경 등)한 뒤 "이 내용으로 다시 옮겨줘" 라고 요청하는 흐름이 흔합니다. 이때:

1. **수정된 CSV를 single source로 다시 Read** 합니다 (메모리상 원본이 아니라 파일을 다시 읽음 — 사용자 수정이 반영된 최신본).
2. 변경 사항(행 수 증감, 수정된 셀)을 간단히 요약해 확인합니다.
3. 3단계에서 정한 출력 방식(클립보드/CSV/Sheets)으로 **그대로 다시 출력**합니다. 새로 생성하지 말고 파일 내용을 그대로 전달하세요.

## 주의사항
- 설계서의 Description 텍스트를 최대한 활용하여 시나리오를 작성합니다
- "터치 시 > [화면ID]" 패턴이 있으면 반드시 이동링크 테스트를 생성합니다
- CASE 분기가 있으면 각 CASE별로 별도 시나리오를 생성합니다
- 외국인/미로그인 등 회원분류별 예외 동작은 빠짐없이 포함합니다
- 시나리오가 너무 많으면 (100건+) 영역별로 분할하여 사용자에게 표시합니다
- 네이티브(앱) / 웹 구분이 있는 경우 각각 별도 시나리오로 작성합니다
- 입력은 Figma URL·PDF·이미지·이미지 폴더를 모두 받습니다. 폴더는 파일명 순으로 정렬해 읽고, 표지·여백 페이지는 스킵합니다
- Figma는 스크린샷을 수십 장 뜨지 말고 `get_metadata` + 동봉 스크립트로 텍스트를 통째로 뽑습니다. 스크린샷은 플로우·레이아웃 확인이 필요한 페이지에만
- 설계서에 "확인 필요"로 남아 있는 미확정 항목은 시나리오를 만들되 예상결과에 `※확정 필요` 를 남깁니다 (누락보다 낫습니다)
- 2차 개발 대상 항목은 "1차에서 미노출되는지" 검증하는 방향으로 시나리오를 만듭니다
- 출력은 회사 계정 환경을 기본으로 **클립보드 복사**를 우선합니다. CSV는 항상 백업으로 남기고, Google Sheets는 권한이 확보된 경우에만 사용합니다
