# Spec Lookup — 설계서 저장소 조회

질문: **$ARGUMENTS**

**설계서는 이 플러그인 안에 없습니다.** 이 스킬은 사내 **설계서 저장소**(비공개 Git 레포)를 그때그때 최신으로 당겨 읽는 **얇은 조회 어댑터**입니다. 설계서 본문은 그 레포에만 있고, HES 저장소나 공개 산출물로 복사하지 않습니다.

이 스킬이 하지 않는 것: 설계서 **작성**(→ `product-spec` 🚧), QA 시나리오 생성(→ `/hes:test-script`), 디자인 시스템 조회(→ `design-system/`).

## 1. 대상 저장소 정하기

**대개 아무것도 안 물어도 됩니다** — 다음 스크립트가 알아서 풉니다. 2단계를 그냥 실행하고, 실패했을 때만 물으세요.

해석 순서(앞이 이김): `--repo` 인자 → `HES_SPEC_REPO` → 프로젝트 `.hes/spec-source.json` → **홈 `~/.hes/spec-source.json`** → **이 머신의 캐시에 레포가 딱 하나면 그것**.

```json
{ "repo": "<owner>/<name>", "ref": "main", "specsDir": "docs" }
```

- **처음 한 번만 묻습니다.** 레포를 받으면 `--repo <owner>/<name> --save-global` 로 실행하세요 — `~/.hes/spec-source.json` 에 저장돼 **다음부터 어느 프로젝트에서든** 자동으로 잡힙니다. 프로젝트마다 다른 설계서를 보는 경우에만 `--save`(프로젝트 `.hes/`)를 쓰세요.
- **캐시로 풀렸으면(`"source": "cache"`) 사용자에게 알리세요** — "이 머신에서 쓰던 <레포>로 조회했습니다"라고 밝히고, 맞으면 `--save-global` 을 권합니다. 후보가 둘 이상이면 스크립트가 고르지 않고 멈춥니다(추측 금지).
- **끝내 못 풀면 짧게 묻습니다** — `owner/name` 한 줄만 요청하세요. 선택지를 늘어놓지 말 것.
- `specsDir` 는 sparse-checkout 할 **문서 루트**입니다(기본 `docs`). 설계서 문서와 조회 계약 파일이 함께 들어오도록 너무 좁게 잡지 마세요.
- 레포 이름을 이 저장소(공개)에 적어 넣지는 않습니다.

## 2. 최신으로 동기화

```bash
node "${CLAUDE_PLUGIN_ROOT}/skills/planning/spec-lookup/scripts/sync-spec-repo.mjs" [--repo <owner>/<name>] [--ref <branch>] [--save-global]
```

`~/.cache/hes/spec-repos/<owner>__<name>` 에 sparse-checkout 캐시를 두고 매번 `origin/<ref>` 로 리셋합니다. 출력은 **캐시 경로 · 커밋 · 커밋 시각** — 그 시각이 "언제 기준 최신인지"의 답입니다.

**항상 먼저 돌립니다.** 캐시가 이미 있어도 건너뛰지 마세요 — 설계서는 자주 바뀌고, **낡은 체크아웃으로 답하는 것이 이 스킬의 유일한 치명적 실패**입니다.

실패하면 원인을 그대로 전합니다. 접근 권한 문제(`Permission denied` · `Repository not found`)면 우회하지 말고 **레포 접근 요청**을 안내하세요 — `gh auth status` 로 지금 로그인된 계정을 확인시키고, 그 계정에 권한을 받아야 한다고 말합니다.

## 3. 그 레포의 조회 계약을 읽는다

동기화된 캐시에서 **`docs/agents/spec-lookup.md`** 를 읽습니다. 레이아웃·라우팅 절차·응답 규율은 **그 파일이 진실**이고 이 SKILL.md 는 그리로 가는 포인터입니다. 절차를 여기 복사하지 마세요 — 레포 구조가 바뀌면 그 파일만 바뀌면 되고, 플러그인 릴리스가 필요 없습니다.

계약 파일이 없는 레포라면 아래 기본 규약으로 진행하되, **추측한 부분을 사용자에게 밝힙니다**:

- 화면 단위 문서는 파일명이 곧 화면ID일 가능성이 높다 → `find <specsDir> -name '<화면ID>.md'`
- `_ROUTING.md` · `_INDEX*.md` 같은 `_` 접두 파일이 있으면 그것이 목차다
- 그래도 못 찾으면 `rg -n '<키워드>' <specsDir>` 로 좁힌 뒤, 히트한 줄이 아니라 **그 줄이 속한 문서 전체**를 읽는다

## 4. 답하기 — 근거 없이 말하지 않는다

계약 파일에 규율이 있으면 그것이 우선합니다. 없을 때의 기본:

- **읽은 문서에 있는 것만 답합니다.** 일반 지식·앱 사용 경험·유사 서비스로 보충하지 않습니다.
- **근거가 없으면 없다고 합니다.** "설계서에 없다"와 "아직 명세되지 않았다(스텁)"를 구분하세요. 문서가 비어 있는 것은 "그 동작이 없다"는 뜻이 아닙니다.
- **인용은 파일 경로 + 문서의 기준일/버전 + 동기화한 커밋**:
  `하나머니/1_N정산하기/CRD_202.md · 기준일 2026-08-24 · 설계버전 v3.11 · 조회 커밋 a097b79`
- 담당자 실명·연락처 같은 개인정보는 옮기지 않습니다. 에스컬레이션은 "담당 파트"까지만.
- **설계서 본문을 외부로 내보내지 않습니다** — 공개 이슈·외부 문서 툴·아티팩트로 옮기기 전에, 비공개 레포 내용임을 사용자에게 먼저 확인시키세요.

## 5. 캐시

`~/.cache/hes/spec-repos/` 는 **비공개 설계서의 로컬 사본**입니다. 사용자가 지워달라고 하면 해당 디렉터리만 지웁니다. 다른 도구가 이 경로를 읽게 만들지 마세요.
