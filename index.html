하나의 소스에서 문서·토큰·컴포넌트를 함께 씁니다.

HDS는 기획·디자인·퍼블리셔가 같은 정본을 공유하고, 코덱스와 클로드에서 동일하게 호출하는 사내 디자인 시스템 하네스입니다. skill · MCP · plugin으로 불러 쓰고, 부서에서 시작해 그룹사 공식 가이드로 확장하도록 설계했습니다.

왜 하네스인가

유지보수를 최우선으로 설계했습니다

내용은 한 곳에만 존재하고, 하네스(클로드·코덱스)와 역할(기획·디자인·퍼블)은 같은 파일을 읽는 얇은 어댑터입니다. 정본을 고치면 모든 곳에 반영됩니다.

1

단일 소스 오브 트루스

토큰·컴포넌트·가이드의 실제 내용은 design-system/에 한 번만 존재합니다. 여기서 고치면 전 하네스·전 역할에 전파됩니다.

2

얇은 하네스 어댑터

클로드 스킬과 코덱스 프롬프트는 같은 파일을 가리키는 얇은 포인터입니다. 하네스가 늘어도 내용은 한 곳에 머뭅니다.

3

2레이어 토큰

core(원시값) → semantic(의미값). 리브랜딩·다크테마·그룹사 테마를 core만 바꿔 대응합니다.

4

표준 포맷

토큰은 W3C DTCG, 컴포넌트는 레지스트리(shadcn 방식). 벤더 종속 없이 장기 유지합니다.

5

명시적 버전 관리

공식 릴리스는 semver + CHANGELOG. 팀은 통제된 시점에만 업데이트를 받습니다.

✳

이 페이지 자체가 데모

지금 보는 색·간격·타이포·모션·컴포넌트는 모두 HDS 토큰으로 그렸습니다. 우측 상단 테마 토글로 다크 오버라이드를 확인해 보세요.

하나의 플러그인, 하나의 정본

한 번 설치하고, 역할별 스킬을 씁니다

플러그인은 hds 하나입니다. 설치 한 번으로 기획·디자인·퍼블 스킬 전체가 들어오고, 모든 스킬이 같은 정본(design-system/)을 봅니다.

skills/design

디자인 — 단일 소스 오브 트루스. 토큰·가이드·컴포넌트 카탈로그·브랜드 비주얼을 관리합니다.

  • design-tokens · design-guide
  • component-catalog · brand-visual
  • figma-bridge · design-reviewer 에이전트
skills/planning

기획 — 제품 설계서를 AI-리더블 문서로 관리하고, 디자인·퍼블 코드 기반으로 프로토타입을 생성합니다.

  • product-spec — 표준 설계서
  • prototype — 동작 프로토타입
skills/publish

퍼블 — 컴포넌트를 개발 적용 코드로 변환하고, 토큰을 export하고, 접근성을 점검합니다.

  • component-build — React/Tailwind
  • token-export — CSS/JSON
  • a11y-audit — 접근성 점검

디자인 토큰 (W3C DTCG)

core → semantic, 두 레이어

원시값(core)을 의미값(semantic)으로 별칭합니다. 컴포넌트는 semantic만 참조하므로, core 한 곳을 바꾸면 전체가 따라옵니다.

Brand scale — color.brand.*

Neutral scale — color.neutral.*

Feedback — color.feedback.*

success · #1f9d55 warning · #a15c00 danger · #e23b3b

warning은 1.2.0에서 흰 텍스트 대비 5.19:1(WCAG AA)을 확보하도록 조정됐습니다.

토큰으로 조립한 컴포넌트

registry.json에 등록된 컴포넌트를 실제 토큰으로 렌더링했습니다. 새 컴포넌트는 spec + 코드 + usage 3종 세트로 추가되고 버전과 함께 배포됩니다.

badge — 5 variants
