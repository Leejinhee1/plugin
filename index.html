디자인 시스템 하네스 · v3.7.0 · Hana Experience System

하나의 소스에서 문서·토큰·컴포넌트를 함께 씁니다.

HES는 기획·디자인·퍼블리셔가 같은 정본을 공유하고, 코덱스와 클로드에서 동일하게 호출하는 사내 디자인 시스템 하네스입니다. skill · MCP · plugin으로 불러 쓰고, 부서에서 시작해 그룹사 공식 가이드로 확장하도록 설계했습니다.

시작하기 GitHub 저장소
/plugin marketplace add Leejinhee1/plugin

왜 하네스인가

유지보수를 최우선으로 설계했습니다

내용은 한 곳에만 존재하고, 하네스(클로드·코덱스)와 역할(기획·디자인·퍼블)은 같은 파일을 읽는 얇은 어댑터입니다. 정본을 고치면 모든 곳에 반영됩니다.

1

단일 소스 오브 트루스

토큰·컴포넌트·가이드의 실제 내용은 design-system/에 한 번만 존재합니다. 여기서 고치면 전 하네스·전 역할에 전파됩니다.

2

얇은 하네스 어댑터

클로드 스킬과 코덱스 프롬프트는 같은 파일을 가리키는 얇은 포인터입니다. 하네스가 늘어도 내용은 한 곳에 머뭅니다.

3

HES 구조 그대로, 4레이어 토큰

core(원시값) → semantic(의미값) → component(HES 컴포넌트 스펙) + platform(AOS·iOS·PC·Min). 리브랜딩·다크테마는 core/semantic만 바꿔 대응합니다.

4

표준 포맷

토큰은 W3C DTCG, 컴포넌트는 레지스트리(shadcn 방식). 벤더 종속 없이 장기 유지합니다.

5

명시적 버전 관리

공식 릴리스는 semver + CHANGELOG. 팀은 통제된 시점에만 업데이트를 받습니다.

✳

이 페이지 자체가 데모

지금 보는 색·간격·타이포·모션·컴포넌트는 모두 HES 토큰으로 그렸습니다. 우측 상단 테마 토글로 다크 오버라이드를 확인해 보세요.

하나의 플러그인, 하나의 정본

한 번 설치하고, 역할별 스킬을 씁니다

플러그인은 hes 하나입니다. 설치 한 번으로 기획·디자인·퍼블 스킬 전체가 들어오고, 모든 스킬이 같은 정본(design-system/)을 봅니다.

개발 현황 — HES는 개발 중입니다. 현재 설치·실행되는 스킬은 ask-hes · mcp-connectors · test-script 3개이고, 준비중 표시된 스킬은 아직 완성되지 않아 호출되지 않습니다. 준비중 스킬의 영역은 design-system/ 정본을 직접 참조하거나 npx hes CLI·design-reviewer 에이전트로 대체할 수 있습니다.
skills/design

디자인 — 단일 소스 오브 트루스. 토큰·가이드·컴포넌트 카탈로그·브랜드 비주얼을 관리합니다.

  • design-tokens · design-guide 준비중
  • component-catalog · brand-visual 준비중
  • figma-bridge 준비중
  • design-reviewer 에이전트 사용 가능
skills/planning

기획 — 제품 설계서를 AI-리더블 문서로 관리하고, 디자인·퍼블 코드 기반으로 프로토타입과 QA 시나리오를 생성합니다.

  • test-script — QA 테스트 시나리오 사용 가능
  • product-spec — 표준 설계서 준비중
  • prototype — 동작 프로토타입 준비중
skills/publish

퍼블 — 컴포넌트를 개발 적용 코드로 변환하고, 토큰을 export하고, 접근성을 점검합니다.

  • component-build — React/Tailwind 준비중
  • token-export — CSS/JSON 준비중
  • a11y-audit — 접근성 점검 준비중
  • npx hes add — CLI 설치 경로 사용 가능

디자인 토큰 (W3C DTCG)

core → semantic → component, 그리고 platform

HES(Figma)의 base → theme → platform 3컬렉션 구조를 그대로 이식했습니다. 원시값(core)을 의미값(semantic)으로 별칭하고, HES 컴포넌트 스펙은 component 레이어(--hes-comp-*)가, 기기별 값은 platform 레이어(AOS·iOS·PC·Min 모드)가 담습니다. 일반 UI는 semantic만 참조하므로 core 한 곳을 바꾸면 전체가 따라옵니다.

컴포넌트 레지스트리 · 13종 stable

토큰으로 조립한 컴포넌트

registry.json에 등록된 13종을 실제 토큰으로 렌더링한 라이브 프리뷰입니다. 각 컴포넌트는 spec + 코드 + usage 3종 세트로 관리되며, 이름 옆 명령을 복사해 HES CLI(npx hes add)로 프로젝트에 바로 설치할 수 있습니다. shadcn CLI 호환 레지스트리도 함께 제공됩니다.

컴포넌트 사용하기

설치하고, import 하면 끝

위 카탈로그의 npx hes add 명령이 실제로 하는 일입니다. HES 자체 CLI가 컴포넌트 소스와 토큰을 프로젝트로 복사해 줍니다 — 별도 호스팅 없이 동작하고, 의존 컴포넌트·토큰은 자동으로 함께 설치됩니다.

1 · CLI 준비

HES 저장소를 개발 의존성으로 추가하면 hes 명령을 쓸 수 있습니다. 사내 npm 레지스트리에 발행했다면 그 패키지명을 쓰세요.

# 저장소를 devDependency 로 (또는 사내 npm 발행본)
npm i -D github:Leejinhee1/plugin

# 설치 가능한 컴포넌트 13종 확인
npx hes list

2 · 컴포넌트 설치

이름만 대면 됩니다. modal 처럼 다른 컴포넌트에 의존하는 경우(modal → button)와 토큰 CSS가 자동으로 함께 설치됩니다. 코드는 components/hes/, 토큰은 styles/hes-tokens.css 로 복사됩니다.

$ npx hes add checkbox

# 여러 개·의존 포함도 한 번에
$ npx hes add modal switch
  + components/hes/Modal.tsx
  + components/hes/Switch.tsx
  + components/hes/Button.tsx   ← modal 의존, 자동 포함
  + styles/hes-tokens.css       ← 토큰, 자동 포함

3 · 토큰 한 줄 로드

모든 컴포넌트는 --hes-* CSS 변수를 참조합니다. 전역 스타일 진입점에서 설치된 토큰을 한 번만 import 하세요. 다크 테마는 <html data-theme="dark"> 로 전환됩니다.

/* app/globals.css (또는 앱 엔트리 CSS) */
@import "./styles/hes-tokens.css";

4 · import 해서 사용

복사된 컴포넌트는 외부 유틸 의존이 없는 자체 완결 파일입니다. 바로 import 해서 씁니다.

import { Checkbox } from "@/components/hes/Checkbox";

export function AgreeRow() {
  return (
    <Checkbox variant="basic" defaultChecked>
      [필수] 서비스 이용약관
    </Checkbox>
  );
}

유용한 옵션

--dir <path>컴포넌트 복사 위치 (기본 components/hes)
--tokens-dir <path>토큰 CSS 위치 (기본 styles)
--force로컬에서 수정한 파일도 덮어쓰기
--registry <url>호스팅된 레지스트리에서 설치

재실행해도 변경 없는 파일은 건너뛰고, 로컬 수정본은 --force 없이는 보존합니다.

다른 소비 경로

  • 패키지 import — 모노레포/사내 npm 에선 barrel 로 바로: import { Button } from "@hes/react"
  • 파일 복사 — 자체 완결 파일이라 <component>/*.tsx 한 개만 복사해도 동작
  • shadcn CLI 호환 — 이미 shadcn 을 쓰는 팀은 같은 레지스트리를 @hes 네임스페이스로 등록해 npx shadcn add @hes/button 으로도 설치 가능(설치 도구만 다를 뿐 소스는 동일).
세 경로 모두 전제는 하나 — 전역에 hes-tokens.css 가 로드되어 있어야 합니다.

역할별 진입점

내 파트에서 무엇을 부르나

역할지금 쓸 수 있는 것준비중코덱스 프롬프트
기획 /hes:test-script product-spec prototype /hes-spec
디자인 design-reviewer 에이전트 design-tokens design-guide component-catalog brand-visual figma-bridge /hes-tokens /hes-component
퍼블 npx hes add token-export registry-export component-build a11y-audit /hes-component
공통 /hes:ask-hes /hes:mcp-connectors — —

스킬은 /hes:test-script처럼 직접 호출합니다. 어떤 걸 써야 할지 모르겠으면 /hes:ask-hes 에 상황을 설명하면 맞는 경로와 — 준비중이라면 그 사실과 대안까지 — 알려줍니다.
