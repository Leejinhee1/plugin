# 보이스 & 톤

> 이 문서는 UI 문구, 알림, 마케팅 카피를 쓰는 사람과 AI를 위한 규범입니다. `identity.md`의 브랜드 가치(명료함·잔잔함·신뢰)를 문장 단위로 구현합니다.

## 1. 보이스 원칙 (상황이 바뀌어도 변하지 않는 것)

1. **차분한 존댓말**: 항상 해요체를 기본으로 한다. 반말·명령형 어미를 쓰지 않는다.
2. **간결함**: 한 문장에 하나의 정보만 담는다. 수식어를 줄이고 동사를 직접적으로 쓴다.
3. **과장·이모지 남용 금지**: 느낌표 연속 사용, 이모지 장식, "대박/최고" 류의 감탄 표현을 쓰지 않는다.
4. **정직함**: 불확실한 예보·지연·오류는 얼버무리지 않고 있는 그대로, 완곡하게 전달한다.
5. **사람을 주어로**: "시스템이 ~합니다"보다 "~해드릴게요/확인해 주세요"처럼 사용자 행동 중심으로 쓴다.

톤은 상황마다 미세하게 조정되지만, 보이스(위 5원칙)는 항상 고정입니다.

## 2. 상황별 톤

| 상황 | 톤 | 좋은 예 | 나쁜 예 |
| :-- | :-- | :-- | :-- |
| 온보딩 | 차분하게 환영, 부담 없는 안내 | "안녕하세요. 오늘부터 하늘이 날씨와 일정을 함께 알려드릴게요." | "환영합니다!! 지금 바로 시작해서 인생 최고의 하루를 만들어보세요 🎉" |
| 오류 | 담담하게 사실 전달 + 다음 행동 제시 | "일정을 불러오지 못했어요. 잠시 후 다시 시도해 주세요." | "오류 발생! 큰일났어요 ㅠㅠ 다시 눌러보세요!" |
| 빈 상태 | 부담 주지 않는 안내, 다음 행동 제안 | "아직 등록된 일정이 없어요. 첫 일정을 추가해 볼까요?" | "텅 비어있네요! 얼른 채워보세요 🔥" |
| 알림(스마트 알림) | 필요한 정보만, 조용한 어조 | "오늘 오후 3시경 비 소식이 있어요. 우산을 챙겨보세요." | "긴급! 지금 당장 우산 안 챙기면 큰일나요!!!" |
| 마케팅 | 담백한 제안, 사실 기반 | "날씨와 일정을 한 곳에서, 하늘로 하루를 준비해 보세요." | "당신의 하루를 지배할 궁극의 필수템, 하늘 지금 다운로드하지 않으면 후회합니다!" |

## 3. UI 문구 스타일 규칙

| 항목 | 규칙 | 예시 |
| :-- | :-- | :-- |
| 존댓말 | 해요체 기본. 버튼·라벨처럼 짧은 UI 요소는 명사형도 허용(예: "저장", "다시 시도"). | "일정을 추가했어요." / 버튼: "저장" |
| 문장부호 | 본문 문장은 마침표를 쓴다. 버튼·라벨·탭 이름 등 짧은 UI 텍스트는 마침표를 생략한다. 느낌표는 원칙적으로 쓰지 않는다(긴급 안전 알림 등 예외는 최대 1개). | 본문: "오늘은 우산이 필요해요." / 버튼: "확인" |
| 숫자 표기 | 아라비아 숫자 사용. 단위는 붙여 쓰되 가독성을 위해 필요한 경우만 띄어쓰기(예: "24°", "3건"). | "최고 24° · 최저 16°" |
| 날짜 표기 | "M월 D일 (요일)" 형식을 기본으로 한다. 연도는 다른 해를 표기할 때만 추가. | "7월 10일 (금)" |
| 시간 표기 | "오전/오후 H:MM" 12시간제를 기본으로 한다. 24시간제는 설정 화면 등 명시적 선택 시에만 노출. | "오후 3:00" |
| 상대 시간 | 하루 이내는 상대 표현, 그 이후는 절대 날짜. | "1시간 뒤", "내일", "7월 12일" |
| 높임 대상 | 사용자에게는 존댓말, 시스템·앱 자신은 낮춰 표현하지 않고 중립적으로("하늘이 알려드릴게요"). | "하늘이 오늘 날씨를 확인했어요." |
