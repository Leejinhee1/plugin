# 브랜드 아이덴티티

제품 UI를 넘어 **브랜드가 드러나는 모든 자산**(아이덴티티·로고·보이스·비주얼·영상)의 규범과 원본을 관리합니다.
`/hds:brand-visual` 스킬이 이 규범을 근거로 자산을 생성/검수합니다.

## 관리 대상

- 브랜드 아이덴티티 정의(미션·비전·가치·퍼스낼리티·네이밍)
- 로고 사용 규칙(여백·최소크기·배경별 사용·금지사례)과 원본 벡터 에셋
- 보이스&톤(문장 단위 브랜드 표현)
- 브랜드 컬러 적용(제품 토큰 `color.brand.*` 와 일관)
- 비주얼 스타일(사진·일러스트·그래픽 모티프)
- 모션 언어(`guidelines/motion.md` 의 이징·듀레이션을 영상에도 적용)

## 원칙

1. **브랜드 자산의 색·모션은 제품 토큰과 같은 언어를 쓴다.** 영상·이미지만 따로 노는 것을 금지한다. 색은 semantic 토큰 이름(`color.brand.default` 등)으로, 모션은 `duration`/`cubicBezier` 토큰으로 기술한다.
2. **원본과 산출물을 구분한다.** `assets/`의 SVG가 원본이며, 이 저장소를 기준으로 관리한다. 파생 렌더링(PNG, 영상 등)은 여기서 재생성될 뿐 원본을 대체하지 않는다.
3. **토큰 값은 여기서 바꾸지 않는다.** 브랜드 컬러(`color.brand.500` 등)는 `tokens/core.tokens.json` 이 유일한 소스다. 이 폴더의 문서는 그 값에 스토리와 사용 규칙을 부여할 뿐, 값 자체를 재정의하지 않는다.
4. **문서는 AI-리더블하게.** 표·명시적 규칙으로 작성해 AI가 이 폴더만 읽고도 브랜드에 맞는 카피·자산을 만들 수 있게 한다.

> Figma의 브랜드 파일과 동기화가 필요하면 `/hds:figma-bridge` 사용.
