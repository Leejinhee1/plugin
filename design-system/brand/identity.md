# 브랜드 아이덴티티

> 이 문서는 사람과 AI가 함께 읽는 규범입니다. 마케팅 카피, 온보딩 문구, 프로모 자산을 만들 때 반드시 이 정의를 근거로 삼습니다.
> 3.0.0에서 가상 브랜드 "(주)하늘" 데모를 **하나머니(Hana Money)** 실브랜드로 교체했습니다. 디자인 언어는 Figma [공식] Hana Experience System(HES)과 동기화합니다. ⚠️ 미션/슬로건 등 카피성 정의는 초안이며 브랜드팀 확정이 필요합니다.

## 0. 한 줄 정리

| 항목 | 내용 |
| :-- | :-- |
| 회사 | 하나카드 (Hana Card) — 하나금융그룹 |
| 제품 | 하나머니 — 통합 멤버십 포인트·페이 서비스 |
| 슬로건(초안) | 쓰고, 모으고, 어디서나 하나머니 |
| 핵심 기능 | 머니 충전·송금 · 포인트 적립/사용 · 결제 내역 브리핑 |
| 디자인 언어 | Hana Experience System (HES) — 하나그린 `color.brand.default`(#009178), Spoqa Han Sans Neo |

## 1. 미션 · 비전 · 브랜드 가치

세 개념은 층위가 다릅니다. **미션은 "왜 존재하는가"**, **비전은 "무엇이 되려 하는가"**, **브랜드 가치는 "어떻게 행동하는가"**입니다. 카피를 쓸 때 이 층위를 섞지 않습니다.

| 구분 | 정의 (초안) |
| :-- | :-- |
| 미션 | 흩어진 포인트와 결제를 하나의 흐름으로 모아, 누구나 돈의 오늘을 쉽게 파악하고 쓰게 돕는다. |
| 비전 | 포인트를 "확인하는" 앱이 아니라, 일상의 결제·적립을 대신 챙겨주는 믿을 수 있는 금융 파트너가 된다. |

### 브랜드 가치 3종

| 가치 | 정의 | 제품에 반영되는 방식 |
| :-- | :-- | :-- |
| 명확함 (Clarity) | 금액·조건·혜택을 숨기지 않고 먼저, 정확하게 보여준다. | 잔액·적립·수수료를 한 화면에서 위계 3단계 이내로 노출(`guidelines/typography.md`). 조건부 혜택은 조건을 같이 표기한다. |
| 신뢰 (Trust) | 하나금융의 신뢰를 UI 디테일로 증명한다 — 값은 항상 검증 가능하고, 오류는 숨기지 않는다. | 색·타이포·간격은 HES 토큰만 사용. 오류·지연은 사실대로 안내하고 다음 행동을 제시한다(`voice-tone.md`). |
| 절제 (Restraint) | 금융 앱의 기본은 차분함 — 강조는 필요한 곳 한 군데에만 쓴다. | 하나그린은 화면당 주요 액션 1개에 집중(`guidelines/color.md`). 모션은 `duration.base` 중심의 진입/퇴장만(`guidelines/motion.md`). |

## 2. 브랜드 퍼스낼리티

하나머니는 사람이라면 이런 모습입니다 — 결제가 끝나면 조용히 적립 내역을 정리해 두고, 물어보면 정확한 숫자로 답하는 꼼꼼한 금융 파트너.

| 이런 성격입니다 | 이런 성격은 아닙니다 |
| :-- | :-- |
| 차분하고 정확함 | 호들갑스럽거나 과장됨 |
| 숫자와 조건을 그대로 말함 | 혜택을 부풀리거나 조건을 숨김 |
| 존댓말로 예의를 지킴 | 반말·유행어로 친근함을 가장함 |
| 필요한 순간에만 알림 | 푸시로 시선을 끌기 위해 소란스러움 |
| 실수를 인정하고 해결책을 제시 | 오류를 얼버무리거나 사용자 탓으로 돌림 |

## 3. 네이밍 규칙

제품명·기능명은 브랜드 가치(명확함·신뢰·절제)를 언어로도 지킵니다.

| 규칙 | 설명 |
| :-- | :-- |
| 기본 표기 | 한국어 서비스명은 "하나머니"(한글, 붙여쓰기) 우선. 영문 병기가 필요하면 "Hana Money". |
| 음절 수 | 기능명은 2~5음절 명사형을 우선한다. 예: 머니 충전, 적립 내역, 결제 브리핑. |
| 그룹 네이밍 준수 | "하나" 접두는 그룹 공식 서비스에만 사용한다. 하위 기능에 "하나○○"를 임의로 만들지 않는다. |
| 과장 금지 | "완벽한", "최고의", "무조건" 등 단정·과장 수식어는 기능명·혜택 표기에 쓰지 않는다(금융광고 심의 관점에서도 금지). |
| 영문 혼용 금지 | 기능명 내부에 영문 약어(AI, Pro 등)를 임의로 섞지 않는다. 필요 시 별도 검토를 거친다. |

| 기능 영역 | 명명 패턴 | 예시 | 금지 예 |
