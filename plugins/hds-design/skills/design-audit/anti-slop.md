# 안티 슬롭 블랙리스트

"AI 슬롭"은 기능은 그럴듯하지만 어디서 본 듯한, 브랜드가 지워진 제네릭 결과물입니다. 아래 항목 각각에 대해 탐지 방법과 교정 방향을 함께 씁니다. Slop Score는 해당 항목 수로 매깁니다(0개=A, 다수=F).

## 범용 (어느 제품에나 나타나는 패턴)

- **보라색/청보라 그라디언트 남발** — 탐지: 배경·버튼·배지에 근거 없는 다색 그라디언트가 반복되는지 본다. 교정: `brand/visual-style.md` §3의 단일 계열(`color.brand.subtle` → `color.brand.default`) 그라데이션만, 그마저도 모티프 규칙 안에서만 쓴다.
- **균일한 중앙정렬 카드 그리드(제네릭 SaaS 룩)** — 탐지: 아이콘+제목+한 줄 설명 카드 3~4개가 기계적으로 반복되는지 본다. 교정: 콘텐츠 성격에 맞는 레이아웃(리스트·타임라인 등)을 먼저 검토한다(`guidelines/principles.md` 원칙 1, 본질 우선).
- **제네릭 히어로 카피** ("~의 힘을 경험하세요", "당신의 하루를 바꿔줄" 류 과장 표현) — 탐지: 구체적 정보 없이 감탄으로 끝나는 문장인지 본다. 교정: `brand/voice-tone.md` 원칙 2(간결함)·3(과장 금지)에 따라 사실 기반 문구로 재작성한다.
- **이모지 장식** (제목·버튼·알림에 이모지 남용) — 탐지: UI 텍스트에 이모지가 있는지 확인한다. 교정: `brand/voice-tone.md` 원칙 3 — 전면 제거한다.

## HDS 고유

- **색/간격 하드코딩(토큰 우회)** — 탐지: 스타일에 semantic CSS 변수 대신 hex/rgb 값이나 임의 px가 있는지 본다. 교정: `/hds-design:design-tokens` 로 대응하는 semantic 토큰을 찾아 치환하고, 없으면 그 스킬로 에스컬레이션해 새 토큰을 만든다.
- **primary 버튼 2개 이상 동시 노출** — 탐지: 한 화면/섹션에 시각적으로 동일한 강조 버튼이 여러 개 있는지 본다. 교정: 하나만 primary로 남기고 나머지는 secondary/tertiary로 낮춘다.
- **semantic이 아닌 core 토큰 직접 참조** — 탐지: `color.brand.500` 같은 core 경로가 코드/스타일에 그대로 노출되는지 본다. 교정: `guidelines/color.md` "참조는 semantic만" 원칙에 따라 semantic alias로 바꾸고, 없으면 `/hds-design:design-tokens` 로 alias를 추가한다.
- **voice-tone 위반(과장·이모지·반말 등)** — 탐지: `brand/voice-tone.md` 5원칙(해요체·간결함·과장 금지·정직함·사람을 주어로)과 화면 문구를 대조한다. 교정: 위반 원칙 번호를 짚고 상황별 톤 표(§2)의 좋은 예 형식으로 재작성한다.
- **브랜드 모티프가 아닌 임의 장식** — 탐지: 수평선·구름·단일 계열 그라데이션 외의 장식(별·불꽃·화려한 패턴 등)이 쓰였는지 본다. 교정: `brand/visual-style.md` §3의 모티프 3종 안에서만 쓰고, 한 화면에 최대 2개까지만 조합한다.
- **danger 색의 장식적 사용** — 탐지: 오류/파괴 상태가 아닌데 강조 목적으로 danger 색(빨강 계열)이 쓰였는지 본다. 교정: `guidelines/color.md` "피드백 색은 의미 고정" 원칙에 따라 강조가 필요하면 brand 색을 쓴다.
