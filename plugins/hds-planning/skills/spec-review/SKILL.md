# 설계서 품질 게이트 (Spec Review)

완성된 설계서가 **낯선 사람이나 AI가 추가 질문 없이 그대로 실행 가능한지**를 검증하고, 필요하면 직접 고친다.

## 평점 루프 (10점이거나 사용자가 멈출 때까지 반복)
1. **평점(0-10)**: "이 설계서만으로 재질문 없이 실행 가능한가?" 기준으로 채점하고 근거를 든다.
2. **10점의 모습 서술**: 지금 문서에 무엇이 더해져야 10점인지 구체적으로 적는다.
3. **직접 수정**: 설계서 파일을 그 기준대로 고친다(설명으로 그치지 않는다).
4. **재평가**: 1로 돌아가 다시 채점한다. 10점이거나 사용자가 중단하면 종료.

## 구체성 검사 (Specificity over vibes)
- "깔끔한/모던한/직관적인" 같은 제네릭 표현을 발견하면 구체 서술로 교체한다(예: "모던한 버튼" → "Button variant=primary, radius `dimension.radius.md`").
- §5 화면 명세가 실제 `hds-design`의 `registry.json` 컴포넌트·토큰 이름으로 되어 있는지 대조한다.
- registry에 없는 컴포넌트를 참조하면 "신규 컴포넌트 후보"로 표시돼 있는지 확인하고, 빠졌으면 채운다.

## 검사 항목
- 수용 기준(§6)이 체크 가능한 문장인가(관찰·측정 가능).
- 화면마다 empty/loading/error 상태가 채워져 있는가.
- 핵심 시나리오(§2)가 "…로서 …하고 싶다, 그래야 …" 형식인가.
- Out of scope(§3)가 비어있지 않은가.
- 미해결 질문(§7)이 본문에 섞이지 않고 분리돼 있는가.

## 통과 후
10점에 도달하면: "`/hds-design:handoff` 로 디자인/퍼블에 전달하세요."
